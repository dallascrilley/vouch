Grounding Context

Codebase Context

Vouch is human review as an API for consensus verification. The loop: an agent POSTs artifacts + acceptance criteria → server-authoritative privacy gate → self-verification → human review via provider adapters (MTurk, local simulator, internal reviewer) → consensus / adjudication → append-only verdict ledger → the agent branches on a structured exit code (0 pass · 1 fail · 2 retry · 3 recapture · 4 escalate · 5 pending). Fastify HTTP API, MCP broker, and CLI transports; SQLite single-node; self-hosted, source-only distribution; privacy- and audit-first posture ("prove offline, self-report live"). Five built-in task templates, all UI/design-focused.

Recurring evidence pattern across the five axis dossiers: the generalization seams are already built but dormant. The broker treats task_template as an opaque string; evidenceRequirements is typed but never consumed; goldTaskPolicy, qualificationRules, and regionOrLocaleRules are declared and never read; criterionProbabilities and the needs_more quorum state exist with no adaptive loop driving them; the provider registry is a hardcoded three-adapter array behind a clean two-method interface; and requestHumanReview() already collapses the five-call protocol into one typed function that no distribution surface exposes.

Past learnings: none — no docs/solutions/ store exists in this repo. Learnings researcher skipped (corpus verifiably absent).

External Context (research value: high)

Closest analog: Tendem by Toloka — "human expert judgment callable at production scale via MCP," 10k+ verified experts, enterprise positioning. Open-source HITL MCP servers (ask_user_text / ask_user_confirm) route questions to the single developer operating the agent — approval, not independent judgment. Framework gates (LangGraph interrupt(), AutoGen UserProxyAgent) are single-human approval patterns, not consensus verification. Market: Toloka $2–10/hr self-serve; Scale AI $15–60/hr managed and losing frontier-lab trust post-Meta stake (neutrality now matters commercially); Prolific ~$350M annualized after pivoting to AI eval; RLHF/human-feedback market $2.8B (2025) → $18.6B projected (2034). Identified gap: nothing combines cheap crowd-consensus voting with a first-class agent tool-call interface. Useful analogies: CI required checks, prediction markets (independent uncorrelated voters), N-of-M code-review quorums.

The Agent-Native Verification Stack

agent-integration Confidence 85% Complexity High

Make human_review a single tool call any agent can afford to make, by shipping three complementary pieces as one product bet: (a) one-call packaging — expose the existing requestHumanReview() abstraction as a first-class MCP tool / Claude Code skill plus generated bindings for OpenAI Agents SDK, LangChain, and AutoGen, instead of today's five 1:1 endpoint-mapped tools; (b) provisional settlement — the agent proceeds immediately on a provisional verdict with an expiry and reversal scope (check-clearing model), and a verification.verdict.reversed event names exactly which commits and artifacts to unwind when human consensus later dissents; (c) a verdict precedent cache — key verdicts on (criterion, evidence contentHash, policy version, material source context) so unchanged content re-verified across retries, rebases, and parallel agents returns the prior human verdict instantly and free, with stare-decisis-style "distinguish on the facts" and explicit-overrule semantics.

Basis
direct: scripts/mcp-broker-server.ts:58-90 — MCP tools map 1:1 to HTTP endpoints, no workflow bundling; scripts/lib/agent-review-client.ts:20-46 — the typed one-call abstraction already exists; exit code 5 (pending) and the "minutes-to-hours latency class" decision at docs/architecture/agent-loop-integration.md:39-46; VisualEvidence.contentHash and source-context fields (src/api/routes/verification-jobs.ts:23-35) already captured, while idempotencyKey dedupes only in-flight requests. external: Reg CC provisional credit / card-network chargebacks; Bazel content-addressed caching; market gap — Tendem is expert-tier and enterprise, HITL MCP servers are single-operator approval; nothing is crowd-consensus and agent-native.
Rationale
This is the direct answer to the prompt's "agent plugin/skill integration" ask. The three pieces attack the three real adoption barriers in order: integration friction (one call, any framework), latency incompatibility (agents run in seconds; humans take minutes-to-hours — provisional settlement makes the check happen behind the agent instead of in front of it), and repeat economics (agent loops re-verify the same unchanged content constantly; caching makes cost O(distinct content) instead of O(runs), and turns the ledger into an appreciating asset).
Downsides
Three moving parts — sequence carefully (packaging first, cache second, provisional third). Reversal semantics push complexity onto the calling agent (what does "unwind" mean after a deploy?). Cache invalidation must be conservative: over-broad reuse silently weakens the human guarantee that is the whole product.

Universal Evidence Envelope + Agent-Trajectory Review

review-domain-generalization Confidence 80% Complexity Medium

Generalize the review path from "screenshot in, vote out" to a typed EvidenceBundle[] with per-type renderers, wire the long-inert evidenceRequirements field so criteria declare what evidence they need, and open the closed five-template union into a criteria-driven template surface. Then ship the flagship vertical this unlocks and nobody else offers: consensus review of an agent's tool-call trajectory — was each step justified, where was the first error — with code-diff review (code_diff + test_output artifact types) as the low-risk first instantiation, and MQM-style span-level error annotation (defect category + severity, aggregated instead of raw votes) as the review mode that finally fills the defect_category / human_annotations fields the agent contract already promises.

Basis
direct: src/domain/artifacts/models.ts:4-14 already declares dom_snapshot | accessibility_tree | console_summary | network_summary | trace_summary | video, while src/domain/human-review/models.ts:28,31-37 narrows everything to visualEvidence?: VisualEvidence; scripts/lib/review-templates.ts:7-13 — closed five-template union; src/domain/jobs/models.ts:32 — evidenceRequirements: string[] semantically inert; AgentFeedback promises defect_category/human_annotations no template can fill; severityRank already implemented (adjudication-service.ts:15-21). external: process supervision is where the $2.8B→$18.6B human-feedback market is heading; MQM/DQF is the ASTM-standardized precedent for typed-error annotation at crowd scale.
Rationale
This is the mechanism behind "use it for much more" — one schema generalization converts five fixed use cases into an open template surface, and the trajectory-review vertical is the single most differentiated position available: consensus-native process supervision, where a screenshot is worthless and every competitor is either single-expert or not agent-native. The verifier rated this the most differentiated idea in the set.
Downsides
Touches three layers (artifact schema, review models, provider bridge rendering), so it needs a deliberate migration. Trajectory review demands higher-skill reviewers than binary screenshot checks — pool quality becomes the binding constraint (pairs with ideas 4 and 5). Renderer work is per evidence type and accumulates.

The Two-Person Rule at the Tool Boundary

agent-integration Confidence 75% Complexity Medium

Every current integration is agent-initiated: the agent decides whether to ask for review, and self-verification can finalize a verdict without any human. Invert the control point, borrowing from nuclear surety and aviation Required Inspection Items: ship Vouch as a harness plugin that intercepts irreversible tool calls (deploy, migration, force-push, external send, spend) at the hook boundary and blocks until vouch returns — the policy lives in the repo/harness config, not in the agent's judgment, and the verifier structurally cannot be the doer. The resulting position is unusual and durable: the only human-in-the-loop layer the agent cannot skip.

Basis
direct: all integration surfaces are agent-initiated (scripts/mcp-broker-server.ts:58-90); src/domain/self-verification/self-verification-service.ts:67-92 — non-escalation actions finalize via verdictService.finalize() without ever touching consensus, so the party being checked currently decides whether the check happens. external: DoD two-person rule; FAA Required Inspection Items (14 CFR 121.369 — the inspector may not be the mechanic who did the work); the grounding's finding that existing HITL MCP servers route to the single operating developer for approval rather than enforcing independent judgment.
Rationale
The verifier called this the strongest strategic idea in the set given current agent-autonomy risk concerns. It converts Vouch from a library an agent may call into a control an operator can rely on — a different product with a different buyer (whoever owns the blast radius, not the agent developer). It also directly closes the self-verification bypass, the largest silent trust gap in the architecture.
Downsides
Requires per-harness hook integration (Claude Code hooks first is the natural wedge). A blocking gate re-creates the latency problem — pair with idea 1's provisional settlement for the medium-risk tier and hard-block only the truly irreversible. Policy authoring is a new UX surface that must stay small.

The Question-Quality Flywheel

consensus-trust Confidence 80% Complexity Medium

Three dormant assets compose into one compounding loop. Discrimination-test templates (triangle / duo–trio from sensory panel science: "which of these three is different?") ask a question class Vouch can't ask today — is this change humanly perceptible at all? — and because the correct answer is known by construction, every task doubles as a free gold task. Gold-task outcomes feed reviewer reputation (implementing the never-read goldTaskPolicy / qualificationRules fields, replacing the binary blocked-flag with calibrated accuracy weighting in consensus). And promoting criteria to a reusable library with disagreement telemetry turns chronic reviewer splits into a signal that the question is defective — the already-collected unclear / not_visible statuses stop being discarded.

Basis
direct: src/domain/human-review/models.ts:135-137 — qualificationRules, goldTaskPolicy, regionOrLocaleRules "defined but never read or evaluated in code"; reviewer-quality-service.ts:4-21 — eligibility is a binary blocked-flag, no accuracy tracking; CriterionStatus already records unclear / not_visible and discards them; TemplateAttentionCheck proves the ground-truth-comparison primitive exists. external: ISO 4120 triangle test / ASTM difference testing — the standard method for statistically defensible verdicts from small untrained panels.
Rationale
The verifier rated this the most mechanistically coherent synthesis: gold tasks generate ground truth → ground truth scores reviewers → scores weight consensus → disagreement telemetry fixes the questions themselves. It is the only direction where the product gets measurably better with use rather than just bigger — reviewer reputation and a calibrated criterion library are assets a competitor cannot copy by shipping features. It is also the trust prerequisite for taking any higher-stakes domain (ideas 2 and 7) to market.
Downsides
Gold-task injection adds per-job overhead cost. Discrimination templates only generate ground truth for perceptibility-class questions — correctness-class gold tasks still need authoring. Reputation systems invite gaming and need decay/rotation design.

Mixed-Substrate Juries

reviewer-providers Confidence 70% Complexity Medium

Nothing in the provider contract asserts a reviewer is human. Register LLM juror panels (N independent models, different vendors/prompts) as first-class providers alongside public-crowd and internal-reviewer, so model votes and human votes enter the same vouch, the same disagreement calculus, and the same ledger — each vote tagged with its substrate. Default policy: the model panel votes first; humans are pulled in as the escalation tier when models disagree or the criterion class is historically miscalibrated. This reframes the product's core noun from "human review" to vouch, and produces a dataset nobody else has: paired human/model verdicts on identical criteria in an append-only ledger.

Basis
direct: ProviderCapabilityProfile (src/domain/human-review/models.ts:141-154) has no field constraining the reviewer to be a person — costModel and latencyProfile are free strings; src/adapters/providers/local-provider-simulator.ts:11-38 already proves a non-human responder flows end-to-end through consensus and the ledger. reasoned: MTurk economics cap the volume Vouch can serve; a model-first / human-escalation ladder is the only structure that keeps "quick + cheap" true at agent-loop volumes while preserving human ground truth where it matters.
Rationale
This is the cheapest path to volumes MTurk can't reach and the natural pairing for idea 1's economics. The paired human/model verdict corpus it generates is the strategic asset — it powers calibration (when can models be trusted per criterion class), pricing, and routing, and it compounds. The related enabling work — converting the hardcoded three-adapter array into a plugin registry, and structuring cost/latency for merit-order routing — slots naturally under this direction.
Downsides
Enters crowded LLM-as-judge territory — the differentiation is the consensus machinery and the human escalation tier, and messaging must protect the "human ground truth" brand. Correlated model votes weaken consensus math (enforce vendor/prompt diversity). Substrate labeling in the ledger must be rigorous or the audit story degrades.

Sequential Adaptive Quorum (SPRT Retirement)

consensus-trust Confidence 75% Complexity Medium

Replace fixed maxAssignments with a sequential stopping rule borrowed from Wald's SPRT and Zooniverse's SWAP retirement: assign one reviewer at a time, update per-criterion posteriors (reviewer-weighted once idea 4 lands), and stop the moment the posterior clears a caller-specified confidence threshold. Unambiguous artifacts terminate after 2 votes; genuinely contested ones escalate on their own evidence rather than on a guess made at dispatch time. "Cheap" stops being a pricing claim and becomes an algorithmic property.

Basis
direct: src/domain/consensus/models.ts:4,26-27 — QuorumState = "met" | "needs_more" | "maxed_out" and criterionProbabilities: Record<string, number> already exist with no adaptive loop driving them; TemplatePricing.max_assignments fixes the count at dispatch. external: Wald's SPRT (sequential acceptance sampling); Zooniverse Space Warps SWAP retirement — the same mechanism proven on citizen-science crowds.
Rationale
The sequential machinery is half-built (three-state quorum, recorded posteriors) and nobody is driving it. It is the largest single unit-economics lever available — 2–3× cost reduction on the easy majority, reallocated to the contested minority — and it is what makes idea 5's escalation ladder principled rather than heuristic.
Downsides
Sequential assignment raises wall-clock latency versus parallel batch dispatch (mitigate: small parallel batches with early-stop between rounds). MTurk's batch HIT mechanics resist one-at-a-time assignment — may fit internal/model pools first. Needs calibrated priors to avoid overconfident early stops; change the budget API before external users depend on fixed-N semantics.

The Compliance & Trust Wedge

distribution-deployment Confidence 65% Complexity High

Everything the deployment dossier files under "limitations" — single-node, self-hosted, no SaaS, source-only — is a procurement requirement in regulated environments (defense, health, financial back offices) where sending artifacts to a public crowd is categorically off-limits. Lean in as a deliberate market position: harden and document the air-gapped posture (the fail-closed, server-authoritative privacy gate is the product); add the compliance evidence types the risk taxonomy already promises (risk_tier accepts "regulated" and "release_gating" today, but no policy-document or audit-citation artifact can back them); support signed professional attestations (identified expert, credential, scope) in the ledger; and make verdicts externally credible with a verdict transparency log — asymmetric signing, real content digests, optional public Merkle log (Certificate Transparency for human judgment) so an auditor can verify "a human quorum passed this build" without seeing the evidence.

Basis
direct: README.md:177-179 — single-node is "deliberate for a service you can run and audit on one box"; src/domain/privacy/privacy-gate.ts:29-68 — externalization is server-authoritative and fail-closed; src/api/routes/verification-jobs.ts:22 accepts "regulated"/"release_gating" while src/domain/artifacts/models.ts:4-14 has no compliance evidence type (a verified internal contradiction); src/domain/feedback/release-artifact.ts — the release attestation is symmetric HMAC (self-verifying only), and some ledger payloadHash values are identifiers, not digests (consensus-service.ts:63, verdict-service.ts:39). external: RFC 6962 Certificate Transparency / Sigstore; market signal that provider neutrality and "who owns the panel" now drive procurement (Scale AI trust fallout).
Rationale
Tendem, Scale, and Prolific are structurally excluded from this segment — they are hosted marketplaces. Vouch's current architecture is not a compromise here but the specification, so entry cost is mostly hardening, evidence types, and positioning rather than new architecture. The transparency log also solves the open-source posture's hardest question — how self-hosted verdicts become credible to outside parties — without a hosted service.
Downsides
A compliance/regulated sales motion is entirely different from dev-tool adoption — hard to run alongside ideas 1–3 without splitting focus. Professional-attestation supply (licensed auditors) is a network Vouch doesn't have. Transparency-log work is standards-grade engineering. Regardless of this direction: the symmetric-HMAC release artifact and identifier-as-payloadHash findings are real weaknesses in a document shipped as externally consumable — worth fixing on their own.
